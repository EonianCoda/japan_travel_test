# Fact Check

審核旅遊文件中的景點資訊是否與網路資料一致，確保數字事實的準確性。

## 工作流程

### Step 1: 掃描目標文件

找出需要驗證的景點資訊，封閉於 `docs/04_attractions/` 目錄。

也接受用戶指定的其他 Markdown 文件。

### Step 2: 找出可驗證的事實 Claims

從文件中提取以下類型的資訊：

| 類型 | 範例 |
|------|------|
| 票價 | ¥500、免費、¥2,000 |
| 開放時間 | 9:00-17:00、終日開放 |
| 休息日 | 每週一休館、年底整備 |
| 地址 | 京都市東山區... |
| 交通費用 | IC ¥240、¥1,500 |
| 設施規模 | 佔地 5,000m² |

**忽略以下無法客觀驗證的資訊：**
- 主觀描述（「很美」、「值得去」）
- 建議停留時間（主觀經驗）
- 美食口感描述

### Step 3: Web Search 驗證

對每個 claim 用 `mcp__MiniMax__web_search` 搜尋驗證。

**搜尋策略：**
- 優先搜「景點名稱 + 官方網站」
- 取第一個可信來源（官方網站、Wikipedia、知名旅遊網）
- 交叉比對多個來源提高準確性

**搜尋關鍵字格式：**
```
「景點名稱」官網 票價 開放時間
「景點名稱」門票 2026
```

### Step 4: 比對結果

將每個 claim 分類：

| 狀態 | 意義 |
|------|------|
| ✅ 已驗證 | 文件值與來源完全吻合 |
| ⚠️ 有出入 | 文件值與來源不符 |
| ❓ 無法驗證 | 找不到可靠來源 |

### Step 5: 寫入審核紀錄

在 `audit/` 資料夾建立驗證記錄。

**目錄結構：**
```
audit/
├── records/
│   └── YYYY-MM-DD.md   # 該日審核結果
├── verified.md          # 已驗證景點清單
└── discrepancies.md     # 待確認項目
```

**records/YYYY-MM-DD.md 格式：**

```markdown
# 景點審核記錄

## 審核日期：2026-05-24
## 目標文件：docs/04_attractions/osaka/osaka_castle.md

### ✅ 已驗證（無問題）

| 景點 | 項目 | 文件值 | 驗證來源 |
|------|------|--------|----------|
| 大阪城天守閣 | 門票 | ¥900 | [官網](https://...) |
| 大阪城天守閣 | 開放時間 | 9:00-17:00 | [官網](https://...) |

### ⚠️ 待確認（有出入）

| 景點 | 項目 | 文件值 | 網路資料 | 備註 |
|------|------|--------|----------|------|
| ... | ... | ... | ... | ... |

### ❓ 無法驗證

| 景點 | 項目 | 文件值 | 嘗試搜尋關鍵字 |
|------|------|--------|----------------|
```

**verified.md 格式：**

```markdown
# 已驗證景點清單

最後更新：2026-05-24

## 大阪

| 景點 | 驗證日期 | 驗證項目 |
|------|----------|----------|
| 大阪城天守閣 | 2026-05-24 | 票價、開放時間 |

## 京都

| 景點 | 驗證日期 | 驗證項目 |
|------|----------|----------|
```

**discrepancies.md 格式：**

```markdown
# 待確認項目

## 需要手動確認的資訊

| 景點 | 項目 | 文件值 | 差異說明 | 備註 |
|------|------|--------|----------|------|
```

### Step 6: 更新主要文件

在驗證完成後，於被審核文件開頭或結尾加上審核標記：

```markdown
> ⚠️ 已驗證（2026-05-24）：票價、開放時間 ✅
```

---

## 驗證原則

1. **只驗客觀事實**：票價、時間、地址等數字和文字
2. **以官方來源為主**：官方網站 > Wikipedia > 大型旅遊網
3. **無法驗證不直接否定**：找不到資料不等於錯誤，標記為「無法驗證」
4. **同一景點不重複驗證**：檢查 `audit/verified.md`，已驗證項目跳過

## 輸出

- `audit/records/YYYY-MM-DD.md` - 當日審核詳細記錄
- `audit/verified.md` - 已驗證景點清單（追加）
- `audit/discrepancies.md` - 待確認項目（追加）
- 更新過的文件加上的驗證標記
